Complete Step 2: the LUT apply stage, and unbreak the Android check

Processing/ColorSpace.swift
- ColorSpace is named on every call, and a LUT/image mismatch is a hard error rather
  than a conversion. This is the section 3.1 rule turned into a type instead of a habit.
- LUTApplicationError is separate from the parse errors on purpose: the file is valid,
  it is just authored for a different colour space, and that is the user's decision to
  make.

Processing/LUTProcessor.swift
- The one place in the app that touches a 3D LUT, so the preview and the saved photo
  cannot drift apart. Two pipelines are how "what you see is what you get" is lost.
- Intensity is a CIDissolveTransition, which is a per-channel lerp, so it is a blend of
  results rather than a blend of lookup tables. Interpolating the table and applying
  that would be a different and wrong operation. CIColorKernel is deprecated and a
  Metal kernel for one lerp is not worth the build risk yet.
- Intensity 0 returns the input untouched, before a texture upload, so a switched-off
  look costs nothing per frame.
- A nil from Core Image is handled. It returns nil for an unsupported filter rather
  than raising, so it is a real branch and the only correct answer is to not apply.

Android
- android-actions/setup-android started failing in its own right, replacing the run
  that had sdkmanager missing from PATH. The action is gone; the command-line tools are
  put on PATH directly, with the known locations probed so a runner image change
  produces a readable failure instead of exit 127.
