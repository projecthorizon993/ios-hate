Record the infrastructure decision: no backend, a versioned format contract

The two apps must produce and read the same files byte for byte, and the only
thing they can share is text formats and an ordered pipeline, not Swift or Kotlin.
So the shared artefact is a contract, not a service.

docs/ARCHITECTURE.md section 9 (new, Testing renumbered to 10)
- What is shared: the recipe grammar, the preset schema, the .cube rules, the
  colour-space rules, the processing order, and a set of byte-exact fixtures.
- Three repositories released independently: the iOS app, the Android app, and
  format-contract. Each pins the contract version it implements, and the file
  itself carries the version so a photo declares which reader it needs.
- Why not a shared library: it couples release cadences, it cannot actually be
  shared between Swift and Kotlin, and a submodule or private package dependency
  would make every build need the network. Data is shared, code is not.
- The contract is a specification plus fixtures, not a comment in somebody's source
  file. Two implementations that pass the same byte-exact fixtures interoperate;
  two that agree on prose do not.
- MAJOR/MINOR/PATCH meanings, and the rule that a reader must accept every version
  at or below its own, which is why unknown keys are skipped rather than rejected.
- Migration order, with the iOS conformance suite before the Android one, because
  iOS is the only implementation that exists and should be measured first.

IOS_CAMERA_APP_PLAN.md
- Section 13 retitled and demoted to a record of what was considered; 13.1 carries
  the decision.
- Removed the now-false claims elsewhere in the plan: the "optional backend" in
  section 2, ATS "for backend traffic" in section 14, the performance dashboards
  "if a backend exists" in phase 11, and the acceptance criterion that the app
  "can launch without a backend connection", which was a degraded mode and is now
  just how it works.
- Two new risks: the two apps drifting apart on formats, and a file written by an
  older app stopping opening.
- Two new execution rules: no format change without a version bump and a fixture,
  and no server or cross-repository build link.
